# Улица-колесо (3DGS)

Сайт: https://street-wheel.vercel.app — деплоится автоматически при пуше в `main` (Vercel).

Длинная улица из Gaussian Splatting (`olaya_3dgs_yup.sog`) свёрнута в колесо: пользователь стоит на
асфальте на «дне» колеса, скроллит — и идёт по кругу. Впереди улица встаёт стеной и уходит над головой.
Вблизи — полная детализация, дальше всё реже, а самое дальнее парит в воздухе отдельными частицами.
Каждый сплат «рождается» частицей и слетается на место по мере приближения.

```
tools/build_ring.py     подготовка данных (Python + numpy)
web/                    вьюер (Vite + TypeScript, без зависимостей, ~40 КБ JS)
  src/ring.ts           математика изгиба и кривая «проявления» (общая для всех)
  src/shaders.ts        WebGL2-шейдер сплатов: изгиб, сборка из частиц, «лимбо»
  src/sort.worker.ts    сортировка по ИЗОГНУТЫМ позициям + пикинг для разметки
  src/decode.worker.ts  загрузка и распаковка кусков
  src/streamer.ts       стриминг LOD по расстоянию вдоль улицы, вытеснение
  src/pois.ts           сноски (DOM поверх canvas)
  public/data/          сгенерированные данные
  public/pois.json      точки интереса
```

## Запуск

```bash
cd web && npm install && npm run dev
```

Сборка для хостинга: `npm run build` → папка `web/dist` (любой статический хостинг).
Файлы `*.bin` уже сжаты gzip и распаковываются в браузере — настраивать сжатие на сервере не нужно;
им стоит выставить долгий кэш.

## Подготовка данных

Модель на самом деле **y-down** (земля на y≈0, здания в отрицательных y), скрипт по умолчанию
поворачивает её на 180° вокруг X. Для y-up модели — флаг `--no-flip`.

```bash
npx @playcanvas/splat-transform olaya_3dgs_yup.sog -H 0 /tmp/olaya_sh0.ply
python3 tools/build_ring.py /tmp/olaya_sh0.ply web/public/data
```

Что делает скрипт: выравнивает ось улицы и уровень земли (иначе концы кольца не сойдутся),
режет коридор, выбрасывает сплаты с непрозрачностью < 2% и крупнее 6 м (12 млн → 6,1 млн),
режет улицу на сегменты по 6 м, внутри сегмента упорядочивает сплаты «по важности со случайностью»
и делит порядок на 6 тиров (3% / 8% / 18% / 40% / 70% / 100%). Любой префикс — равномерно
разрежённая версия сегмента, поэтому LOD = сколько тиров загружено.

Главные параметры: `--s-range` (какой участок станет кольцом; сейчас 305 м → радиус 48,5 м),
`--seam-width`, `--min-opacity`, `--tiers`, `--seg-len`, `--seam-particles`.

| | размер |
|---|---|
| первый кадр (частицы всего кольца) | 2,9 МБ |
| частицы шва | 2,0 МБ |
| детали вокруг одной точки: high / mid / low | ~21 / ~16 / ~9 МБ |
| всё целиком | 88 МБ (≈13,7 байт на сплат) |

## Как устроено

- **Изгиб.** Камера стоит на месте, мир сворачивается вокруг неё: `θ = κ·d`, где `d` — расстояние вдоль
  улицы до пользователя. Ковариации сплатов умножаются на якобиан изгиба, поэтому сплаты не рвутся.
  Сортировка в воркере идёт по уже изогнутым позициям (LUT по s): на кольце порядок смешивания
  совсем не такой, как на прямой улице.
- **Проявление.** Доля видимых сплатов падает как `(densNear / d)^densPow` — стохастический
  «дизеринг» по рангу. Сплат у порога видимости появляется частицей, смещённой в воздухе, и
  слетается на место; вдали всё сжато в точки и медленно парит. Значения по умолчанию —
  `DEFAULTS` в `src/tune.ts`, остальное (шов, поперечный срез) — `DEFAULT_REVEAL` в `src/ring.ts`.
- **Шов.** Концы улицы растворяются в частицы (`seamInner/seamOuter`), а в зоне стыка лежит облако
  из 280 тыс. частиц, «вытянутое» из профилей обоих концов, поэтому стыка не видно.
- **Стриминг.** Загружаются только тиры, нужные сегменту на его расстоянии; впереди по ходу — в
  первую очередь. Догруженные куски прилетают роем частиц, а не появляются целиком.
  Пул на GPU страничный (20 байт на сплат), лишнее вытесняется.
- **Под слабые устройства.** Профили `low/mid/high` выбираются по устройству (телефон → low), затем
  адаптивно по времени кадра: сначала снижается разрешение, потом радиус деталей.

## Рассказ «City world model»

Прогулка — интерактивный рассказ из шести глав, разложенных по кольцу: Capture → Quality gate →
Detection → Asset registry → Case → Reupdated. Всё привязано к позиции на кольце, а не ко времени,
поэтому рассказ «прокручивается» вперёд и назад вместе с улицей:

- заставка с заголовком, шкала глав сверху (клик — переход), колесо-схема цикла справа внизу;
- панель главы проявляется и уходит по скроллу, виджеты внутри тоже «скрабятся» скроллом
  (проверка кадров, список детекций, реестр, кейс, «починили → закрыто»);
- метки на объектах: рамки детекций и ярлыки ассетов появляются вместе со строками в панели;
- **каждый второй круг — лендинг**: сама улица «стекает» в белую ленту на ободе колеса — частицы
  зданий, деревьев и асфальта слетаются к полу, сжимаются по ширине и окрашиваются в цвет страницы
  в том месте, куда прилетели (переход — первые 40 м после шва). Поверх ленты досбирается страница
  (заголовок, схема цикла, шесть шагов с картинками), сгенерированная в браузере (`src/landing.ts`):
  рисуется на canvas и превращается в сплаты — бумага плоскими сплатами, текст и картинки круглыми
  точками (плоские под острым углом вытягивались бы в полосы) со случайным сдвигом против муара.

Текст и метки — в `web/public/story.json` (`chapters[].start` — где на кольце начинается глава,
`short` — строка для лендинга; `markers[]` — метки с `kind: detection | asset`). Картинки
лендинга — `web/public/landing/*.jpg`, это чистые кадры самой сцены (`?clean` прячет интерфейс).
Рамки на картинке детекций заданы в долях кадра в `src/landing.ts`. Рамки детекций в рассказе
стоят на настоящих объектах сцены, но сами «нарушения» иллюстративные.

## Сноски

`web/public/pois.json`:

```json
{ "id": "x", "tag": "01", "title": "…", "text": "…", "image": "…", "link": "…", "street": [s, h, w] }
```

Координаты: откройте `?edit` или нажмите **E**, кликните по объекту — JSON с координатами
скопируется в буфер обмена. Можно также указать `"model": [x, y, z]` в координатах исходной модели
(например, из SuperSplat): они пересчитаются тем же преобразованием, что и данные.

Сноски сделаны обычным DOM поверх canvas: чёткий текст, доступность, работает везде.
HTML-in-Canvas (`texElementImage2D`) пока в origin trial только в Chrome, и API ещё меняется. Позже
его можно включить как улучшение: карточки тогда станут частью 3D-сцены (будут гнуться вместе
с колесом и рассыпаться в частицы), а для остальных браузеров останется DOM.

## Живая настройка

Кнопка со слайдерами в правом верхнем углу открывает панель: парение, разлёт и сборка частиц,
скорость прилёта догруженного, кривая «проявления», камера, чувствительность скролла.
Значения применяются сразу и запоминаются в этом браузере. «Копировать» отдаёт JSON — его можно
вписать в `DEFAULTS` в `web/src/tune.ts`, чтобы так стало у всех. Двойной клик по строке
возвращает значение по умолчанию. Для публичной версии кнопку можно скрыть: `?notune`
(или убрать создание `TunePanel` в `main.ts`).

## Параметры URL

`?debug` — статистика (Shift+D), `?q=low|mid|high`, `?s=55` — стартовая точка, `?eye=1.7` — высота
глаз, `?lane=-8` — полоса (поперечная координата), `?pitch=0.3`, `?fov=78`, `?exp=1.15` — экспозиция,
`?nointro`, `?edit`, `?clean` — только сцена, `?landing` — сразу на круг-лендинг, `?nolanding` — без него, `?notune` — без панели настроек,
`?data=папка` — A/B-сравнение разных сборок данных из `public/`.

## Что не сделано / идеи

- SH (view-dependent цвет) отброшены ради размера. Можно вернуть 1-й порядок для ближних тиров.
- Сжатие: 13,7 байт на сплат; webp-кодирование, как в SOG, дало бы около 10.
- Производительность проверена только на Apple M4 (≈9 мс GPU на 0,5 млн сплатов в 2,5 Мп).
  На реальных телефонах не проверялось.
- `splat-transform -F` (фильтр «флоатеров») с `-B`-кропом вырезал здания (видимо, у бокса другая
  система координат), поэтому в пайплайне его нет.
